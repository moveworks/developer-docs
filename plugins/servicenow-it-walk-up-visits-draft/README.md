# Description

Gives employees a conversational front door to ServiceNow's Walk-Up Experience: book a Tech Lounge appointment (in-person, remote, or either), check in to a walk-in queue and get a real queue position, or view and cancel an existing appointment or queue entry — all without leaving chat.

# Pre-requisites

Before installing and using the **IT Walk-up Visits** plugin, ensure the following requirements are met.

## 1. Employee Slate for ITSM + ServiceNow Walk-Up Experience

Requires **Employee Slate for ITSM** (`sn_itsm_empworks`) **v2.0.3 or later**, which ships the `walk_in/*` Scripted REST API this plugin depends on. Also requires ServiceNow's **Walk-Up Experience** plugin (`com.snc.walkup`) to be active — confirm this **before** installing Employee Slate for ITSM. See ServiceNow's [**Walk-up Experience**](https://www.servicenow.com/docs/r/it-service-management/walk-up-experience/walkup-experience-landing-page.html) documentation.

Also required: **Appointment Booking** (`sn_apptmnt_booking`) and **Service Catalog** with a configured Tech Lounge booking catalog item.

## 2. User Identity Resolution

This plugin resolves the requester's ServiceNow `sys_user` sys_id by email early in the conversation and threads it through as `userId` on every `walk_in/*` call, since there is no per-user OAuth identity to dot-walk under a shared service account.

## 3. ServiceNow Connector

This plugin uses **Service Account authentication** (OAuth 2.0 Client Credentials). Scope the service account to read access on `wu_location_queue`, `wu_m2m_location_queue_reason`, `interaction`, and `sys_user`, plus write access on `wu_appointment` and `interaction`.

Follow the [**OAuth 2.0 Client Credentials guide**](https://marketplace.moveworks.com/connectors/servicenow#oauth-2-0-client-credentials) to configure the connector, then follow the [**plugin installation documentation**](https://help.moveworks.com/docs/ai-agent-marketplace-installation) to install and activate the plugin in **Agent Studio**.

# How This Plugin Works

The plugin routes on a `book_or_queue` slot with three flows, each running its own duplicate-booking check independently:

- **Book an appointment.** Checks for an existing appointment (offers cancel-and-rebook if found), resolves the location's supported contact type(s), checks slot availability, collects a reason, and submits through the Tech Lounge catalog item behind a native confirmation gate.
- **Join the walk-in queue.** Checks for an existing queue entry, verifies the location is not remote-only, then checks the employee in via `/checkin` behind a native confirmation gate and reports a real queue position.
- **View / manage.** Looks up both the active appointment and queue entry together and offers cancellation. Cancelling either flips the underlying `interaction` to `closed_abandoned` — no records are deleted.

## API Details

### Custom REST API — `walk_in` service (`sn_itsm_empworks`)

All routes are `POST`, JSON in/out, always return HTTP 200. Success or failure is signaled via a field in the body (`checkedIn`, `cancelled`), not the HTTP status code. Every route requires the real employee's `sys_user` sys_id passed as `userId`.

| Route | Purpose |
|---|---|
| `/checkin` | Check the employee into a location's walk-in queue. |
| `/cancel` | Cancel a walk-in queue entry or appointment. |
| `/locations` | List active Tech Lounge locations with contact-type fields. |
| `/active-queue` | Look up the employee's active walk-in queue entry. |
| `/queue-count` | Count active queue entries ahead of a given time. |
| `/active-appointment` | Look up the employee's active/upcoming appointment. |
| `/appointment-state` | Recheck an appointment's state after a write. |

### Standard ServiceNow APIs

- **Table API reads** — `wu_location_queue`, `wu_m2m_location_queue_reason`, `interaction`, `sys_user`.
- **Appointment availability** — `GET /api/sn_apptmnt_booking/appointment/availability`.
- **Catalog producer submit** — `POST /api/sn_sc/servicecatalog/items/{catalog_id}/submit_producer`.

For API reference details, see ServiceNow's [**Table API**](https://docs.servicenow.com/bundle/latest-application-development/page/integrate/inbound-rest/concept/c_TableAPI.html) and [**Service Catalog API**](https://docs.servicenow.com/bundle/latest-application-development/page/integrate/inbound-rest/concept/c_ServiceCatalogAPI.html) documentation.

# What Is In Scope for This Plugin?

- Booking a Tech Lounge appointment at in-person-only, remote-only, or either-type locations.
- Detecting an existing appointment or queue entry before starting a new one.
- Offering to book a new appointment after cancelling one in an appointment context.
- Redirecting a walk-in request into the full booking flow when the location is remote-only.
- Joining a location's walk-in queue and reporting a real queue position.
- Viewing an employee's existing appointment and walk-in queue entry together.
- Cancelling an existing appointment or walk-in queue entry.

# What Is Out of Scope for This Plugin?

- Rescheduling an existing appointment (cancel and rebook only).
- Walk-in queue join for remote-only locations.
- Creating or managing Tech Lounge locations, schedules, or reason categories.
- Acting on behalf of another employee.
