# Description

Employees accumulate tasks and approvals across multiple categories — IT approvals, onboarding tasks, learning assignments, and delegated work — but checking on them means navigating the ServiceNow portal. The Moveworks AI Assistant brings all of that into chat: the employee asks, the assistant maps their words to filters configured in the ServiceNow instance, and returns matching open work in a single table. V1 is retrieval only; no action is taken on tasks from chat.

# Pre-requisites

## 1. ServiceNow instance

- The ServiceNow instance must be on the **AP6 patch** or later.
- The configuring admin must have permission to create **OAuth inbound integrations** in ServiceNow.
- Test users with representative open tasks and approvals must exist in the target ServiceNow instance before validating the plugin.

## 2. ServiceNow OAuth connector

This plugin requires an active **ServiceNow connector** configured with **OAuth 2.0 using the Authorization Code grant (user-based / User Consent auth)**. The connector must act in the signed-in user's context so ServiceNow can apply assignment conditions, delegation rules, and access controls correctly.

- If you have not already configured the connector, follow the [**OAuth 2.0 Authorization Code guide**](https://docs.moveworks.com/agent-studio/connectors/http-connectors/oauth-20-authorization-code). The connector must be fully set up before installing this plugin.
- After the connector is configured, follow the [**plugin installation documentation**](https://help.moveworks.com/docs/ai-agent-marketplace-installation) for detailed steps on how to install and activate the plugin in **Tool Studio**.

## 3. Disable native approval plugins

To prevent conflicts with built-in ServiceNow approval handling, set the user filter rule to `FALSE` for both the **Update Approval Record Plugin** and the **Approval Information Plugin (List of Approvals)** in the AI Assistant plugin management settings before deploying.

> ⚠️ **Important** — Leave the Deflection Message field empty unless your configuration explicitly requires it. If either rule remains active (not `FALSE`), native approval workflows will continue running and conflict with this plugin.

# How This Plugin Works

- **Retrieve open tasks.** The assistant maps the employee's words to filters configured in the ServiceNow instance and returns matching open tasks and approvals in a table.
- **Apply filter combinations.** Supports AND combinations across different filter categories, and OR combinations within the same filter category.
- **Complete task in split view.** Employees can open individual task records for further action in split view.

Task retrieval runs in the signed-in user's context — ServiceNow applies that user's assignment conditions, delegation rules, and access controls on every call.

# What Is In Scope for This Plugin?

- Retrieve open tasks and approvals for the signed-in employee
- Retrieve work using filters configured in the target ServiceNow instance
- Resolve supported synonyms to configured filters
- Support AND combinations across different filter categories
- Support OR combinations within the same filter category
- Complete task action in split view

# What Is Out of Scope for This Plugin?

- Approve, reject, complete, comment on, or sign work from chat
- Open task or approval records directly from chat
- Look up work by task number
- Filter by task details such as name, title, amount, table name, or other task response fields
- Use filters not configured in the target ServiceNow instance
- Support OR logic across different filter categories
