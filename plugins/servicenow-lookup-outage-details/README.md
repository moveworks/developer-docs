# Description

Lets employees get a read-only view of IT and service outages right from the Moveworks AI Assistant — no ServiceNow portal, no dashboard hunting. Ask about outages happening right now, filter to a service or configuration item, see planned maintenance windows or degradations, or scope to a date range in plain language ("outages started between July 5 and July 11"). The plugin translates the request into a single ServiceNow query against the outage table, returns the most relevant results newest-first summarized in plain language, and offers up to three follow-up suggestions to narrow down further. It reads only — nothing is created or changed.

# Pre-requisites

Before installing and using the **Outage Lookup** plugin, please ensure the following requirements are met:

## **1. ServiceNow Outage Table**

This plugin reads from the ServiceNow **Outage** table (`cmdb_ci_outage`), which is part of the platform's CMDB / IT Service Management data model. Outage records must exist and be populated on your instance for the plugin to return results. No additional ServiceNow Store application is required beyond a standard ITSM/CMDB-enabled instance.

## **2. ServiceNow Connector**

This plugin requires an active **ServiceNow connector** configured with **OAuth 2.0 using the Client Credentials grant (service account)**. The single GET lookup runs under a **dedicated service account**, scoped to a role limited to read-only access on the outage table this plugin needs (`cmdb_ci_outage`) — no standing access beyond that.

A service-account connector is used here because the target user is the **requester**, who typically does not have direct read access to the CMDB outage tables. Running the lookup under the service account lets any requester retrieve outage information regardless of their own ServiceNow ACLs, while keeping the service account's own permissions tightly scoped to this plugin's needs.

If you have not already configured the connector, please follow the [**OAuth 2.0 Client Credentials guide**](https://marketplace.moveworks.com/connectors/servicenow#oauth-2-0-client-credentials). The connector must be fully set up before installing this plugin.

Once the connector is configured, follow our [**plugin installation documentation**](https://help.moveworks.com/docs/ai-agent-marketplace-installation) for detailed steps on how to install and activate the plugin in **Agent Studio**.

# **Implementation Details**

## API Details

All calls run against the customer's ServiceNow instance. Replace `YOUR_INSTANCE` with your ServiceNow instance hostname and `ACCESS_TOKEN` with the access token for the configured connector.

### **API #1: List / Look Up Outages**

Returns outage records from `cmdb_ci_outage` matching the composed query. Whatever filters the user supplied are AND-combined into a single encoded query and ordered newest-first:

```bash
curl --location 'https://<YOUR_INSTANCE>/api/now/table/cmdb_ci_outage?sysparm_query=<COMPOSED_QUERY>^ORDERBYDESCsys_created_on&sysparm_display_value=all&sysparm_limit=25&sysparm_fields=<FIELD_LIST>' \
  --header 'Authorization: Bearer <ACCESS_TOKEN>' \
  --header 'Accept: application/json'
```

**Query parameters (composed into `sysparm_query`):**

- `outage_type` *(string, optional):* One of `Planned` / `Degradation` / `Unplanned` (backed by a static resolver). Produces a `type=` clause.
- `active_only` *(boolean, optional, default false):* When true, restricts to outages that have not ended — `end > javascript:gs.nowDateTime() ^OR end IS EMPTY`.
- `search` *(string, optional):* Free-text service/CI search. Produces `cmdb_ci.nameLIKE<value> ^OR 123TEXTQUERY321=<value>`.
- `timeframe_query` *(string, optional):* Natural-language date range. A mid-process LLM step parses it into `date_field`, `date_from`, and `date_to`, which become `>=` / `<=` clauses on the chosen date field (e.g. `begin`, `end`, `sys_created_on`).

**Request parameters:**

- `sysparm_display_value=all` — return both display and raw values.
- `sysparm_limit=25` — hard cap of 25 rows; when hit, the response surfaces a limit note advising the user to narrow the query.
- `sysparm_fields` — a fixed field list (`type`, `cmdb_ci.name`, `begin`, `end`, `duration`, `short_description`, `message`, `sys_created_on`) so the payload is trimmed before it reaches the model.

**Key nuances:**

- **Null-safe query construction.** Empty filter clauses are dropped rather than sent as empty conditions, so an unspecified filter never returns zero rows by accident.
- **Read-only.** This is the only outbound call; there is no create/update/delete path, so no confirmation step is required.
- **Requestor-facing output.** Results are summarized in plain language for end users; internal record numbers and backend ServiceNow deeplinks are intentionally not surfaced.

### API References

For detailed information on request parameters, response formats, and error handling, refer to the official [**ServiceNow Table API**](https://docs.servicenow.com/bundle/latest-application-development/page/integrate/inbound-rest/concept/c_TableAPI.html) documentation.

# **What Is In Scope for This Plugin?**

- Listing IT and service outages from ServiceNow's outage table.
- Showing outages that are currently active ("happening right now").
- Filtering by outage type (Planned / Degradation / Unplanned).
- Filtering by affected service or configuration item via free-text search.
- Scoping results to a natural-language date range (begin, end, or created dates).
- Returning results newest-first, summarized in plain language with follow-up suggestions.
- Surfacing a clear note when results are capped at 25.

# **What Is Out of Scope for This Plugin?**

- Creating, updating, resolving, or closing outage records (this plugin is read-only).
- Acknowledging outages or subscribing to outage notifications.
- Proactively pushing alerts when a new outage is opened.
- Root-cause analysis, incident correlation, or impact assessment beyond the fields returned.
- Looking up outages across systems other than ServiceNow.
- Returning more than 25 records in a single response (the user is prompted to narrow instead).
